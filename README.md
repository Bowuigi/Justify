# Justify

A suite for prototyping, documenting, interpreting, testing and working with logical systems (and programming languages) expressed in terms of inference rules.

This repo includes the [JSON Type Definition](https://jsontypedef.com) format specifications in `formats/*.jtd.json` files. The specification is meant to include three formats:

- **System**: The full logical system description, including its syntax and logical relations.
- **Query**: A single query to a **System** file.
- **DerivationTree**: Derivation trees corresponding to query results, possibly generated by the microKanren implementation in this project.

This project is also meant to contain general tooling (all WIP, see the [issues](https://github.com/Bowuigi/Justify/issues) and [pull requests](https://github.com/Bowuigi/Justify/pulls) tabs for progress information and available tasks):

- A **validator** that checks that the files are correct.
- An **inferencer** that takes a System and a Query on it and returns a DerivationTree with the query results (human-readable or in JSON).
- Various **generators** that turn other formats into Justify files
  - *(Deprecated)* A Tcl DSL that generates System and Query files.
  - A [remark](https://github.com/remarkjs/remark) (Markdown) extension that generates System files.
- Various **extractors** that turn those formats into other formats for external uses.
  - A LaTeX and KaTeX compatible TeX extractor.

The subproject folders have separate README and example files documenting their usage.

## Why?

Some reasons:

- Understanding how type systems work with your imagination or custom typecheckers is complex, time-consuming and error-prone.
- Maintaining formal specifications (either as documentation or as a reference) of a logical system without being able to test and compare them with an implementation is hard and leads to specification drifting.
- Prototyping a programming language is usually a time-consuming process with uncertain results, causing endless brainstorming, fights with tooling (or ignoring it entirely) and eventually a bunch of discarded code.

Justify is meant to be open in order to ease integration with external tools such as theorem provers, code generators, structural editors, etc.

Other goals of this project include prototyping, documentation and automation of various concerns related to programming language design, verification and implementation.
